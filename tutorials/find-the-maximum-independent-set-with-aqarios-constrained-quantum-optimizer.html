Găsește Maximum Independent Set cu Aqarios Constrained Quantum Optimizer

Notă

Qiskit Functions este o funcționalitate experimentală disponibilă doar utilizatorilor IBM Quantum® Premium Plan, Flex Plan și On-Prem (prin IBM Quantum Platform API) Plan. Acestea au statutul de preview release și pot suferi modificări.

Estimare de utilizare: 30 de secunde pe un procesor Heron r2. (NOTĂ: Aceasta este doar o estimare. Timpul tău de execuție poate varia.)

Context​

Acest tutorial demonstrează cum să găsești mulțimea independentă maximă a unui graf folosind Aqarios Constrained Quantum Optimizer [1], o problemă de optimizare combinatorică cu restricții. O instanță din biblioteca de benchmark QOBLIB [2] este formulată ca un program liniar binar și transmisă Optimizer Application Function. Optimizatorul se ocupă intern de toate reformulările, sinteza circuitului, transpilarea și warm-starting-ul iterativ (vezi [3] pentru detalii).

Tutorialul acoperă următorii pași:

  1. Definește problema ca un program liniar folosind OptimizationProblem din qiskit-addon-opt-mapper

  2. Rulează optimizarea cuantică folosind Aqarios Constrained Quantum Optimizer

  3. Preia și vizualizează rezultatele

Problema Maximum Independent Set​

Problema Maximum Independent Set (MIS) este o provocare fundamentală în optimizarea combinatorică. Formal, dat fiind un graf G(V,E)G(V, E)G(V,E), scopul este să găsim cea mai mare submulțime de vârfuri VI⊂VV_I \subset VVI​⊂V astfel încât niciun doi vârfuri din VIV_IVI​ să nu fie conectate printr-o muchie, ca în ∄(u,v)∈E:v∈VI∧u∈VI\nexists (u, v) \in E : v \in V_I \wedge u \in V_I∄(u,v)∈E:v∈VI​∧u∈VI​. Fiecărui vârf i se atribuie o variabilă de decizie binară xi∈{0,1}x_i \in \{0, 1\}xi​∈{0,1}, și pentru fiecare muchie se introduce o restricție xu+xv≤1x_u + x_v \leq 1xu​+xv​≤1, asigurând că cel mult un capăt al fiecărei muchii este selectat. Problema poate fi astfel formulată ca următoarea problemă de maximizare:

max⁡xi∑i∈Vxi(ga˘sește cea mai mare mulțime)a.ıˆ.xu+xv≤1∀(u,v)∈E.\max_{x_i} \sum_{i \in V} x_i \qquad\text{(găsește cea mai mare mulțime)}\\ \text{a.î.} \quad x_u + x_v \leq 1 \quad \forall (u, v) \in E.xi​max​i∈V∑​xi​(ga˘sește cea mai mare mulțime)a.ıˆ.xu​+xv​≤1∀(u,v)∈E.

MIS are o gamă largă de aplicații practice. În planificarea rețelelor wireless, o mulțime independentă corespunde unui grup de emițători care pot transmite simultan fără interferențe reciproce. În planificarea sarcinilor, modelează cea mai mare colecție de sarcini care pot fi executate concurent, având în vedere conflictele de resurse pe perechi. În biologia computațională, capturează mulțimi de proteine care nu interacționează reciproc într-o rețea.

În ciuda formulării sale intuitive, MIS este NP-hard, iar chiar și pentru grafuri cu câteva sute de noduri, anumite instanțe devin dificil de rezolvat exact sau euristic [2]. Problema generează, de asemenea, structuri de restricții rare, care sunt bine potrivite pentru implementările hardware ale optimizării cuantice, făcând din ea un benchmark atractiv pentru dispozitivele cuantice de generație apropiată.

Aqarios Constrained Quantum Optimizer​

Abordarea standard pentru încorporarea unei probleme binare cu restricții în optimizarea cuantică transformă modelul într-un format fără restricții prin adăugarea de termeni de penalizare: fiecare restricție încălcată xu+xv≤1x_u + x_v \leq 1xu​+xv​≤1 contribuie cu 2xuxv2 x_u x_v2xu​xv​ la obiectivul de minimizare −∑ixi-\sum_i x_i−∑i​xi​. Acest lucru este gestionat automat de Constrained Quantum Optimizer Qiskit Function.

Dincolo de această transformare standard, optimizatorul identifică clici în graful de restricții. O clică este o mulțime de noduri VCV_CVC​ în care fiecare pereche de noduri împarte o muchie. Ca urmare, cele (∣VC∣2)\binom{|V_C|}{2}(2∣VC​∣​) restricții pe perechi xu+xv≤1  ∀(u,v)∈ECx_u + x_v \leq 1 \;\forall (u,v) \in E_Cxu​+xv​≤1∀(u,v)∈EC​ pot fi înlocuite cu o singură restricție mai strictă ∑i∈VCxi≤1\sum_{i \in V_C} x_i \leq 1∑i∈VC​​xi​≤1. Introducerea unei variabile de compensare (slack) yyy transformă aceasta într-o egalitate ∑ixi+y=1\sum_i x_i + y = 1∑i​xi​+y=1, care ia forma unei restricții one-hot ce poate fi impusă direct în QAOA folosind XY-mixers [3]. Aceasta reduce spațiul de căutare și evită nevoia de termeni de penalizare pentru acele restricții, îmbunătățind calitatea soluției.

În plus, variabilele conectate la un singur vecin sunt numite noduri pendant și sunt fixate în mod determinist de algoritm înainte de execuția cuantică, reducând și mai mult dimensiunea efectivă a problemei.

Constrained Quantum Optimizer folosește o abordare de warm-starting iterativ compatibilă cu XY-mixers [1], care restrânge progresiv spațiul de căutare prin direcționarea distribuției stării cuantice către regiuni de soluții promițătoare de-a lungul iterațiilor. Acest lucru permite utilizarea parametrilor QAOA cu unghi fix, eliminând nevoia de antrenare a parametrilor variaționali. Cerințele totale de resurse cuantice sunt determinate exclusiv de numărul de iterații de warm-start, ceea ce face ca costul cuantic să fie ușor de controlat.

Pasul 1: Mapează intrările clasice la problema cuantică​

Problema este formulată ca un fișier LP, un format comun pentru problemele de optimizare care servește drept intrare pentru Aqarios Constrained Quantum Optimizer. Pe lângă fișierele LP, funcția acceptă și fișiere MPS și reprezentări native Luna Model. Fișierul LP este generat prin următorii pași:

  1. Preia o instanță de graf din QOBLIB [2]

  2. Modelează problema de optimizare

  3. Generează fișierul LP

Încarcă graful instanței problemei​

Grafurile sunt specificate în formatul DIMACS .gph, un format bazat pe linii, unde liniile care încep cu e definesc muchii, liniile care încep cu p definesc antetul problemei, iar liniile care încep cu c sunt comentarii:

c some-comment
p edge 3 2
e 1 2
e 2 3
...

Fișierul .gph poate fi descărcat din repozitoriul QOBLIB folosind următoarea funcție, care îl parsează și într-un graf NetworkX. Reține că formatul DIMACS folosește etichetarea nodurilor începând de la 1, care aici este convertită la indexare începând de la 0.

URL_BASE = "https://raw.githubusercontent.com/ZIB-AOPT/QOBLIB/refs/heads/main/07-independentset/instances/"

def fetch_qoblib_graph(name: str) -> nx.Graph:
    """Fetch and parse the QOBLIB graph file."""
    # Download the .gph file
    file, _ = urllib.request.urlretrieve(URL_BASE + f"{name}.gph")
    with open(file) as f:
        # Read the file contents
        lines = f.readlines()

    # Skip comments
    lines = [line for line in lines if not line.startswith("c")]

    # Read graph definition
    _, _, num_nodes, num_edges = lines[0].split()
    print(f"Loading graph with {num_nodes} nodes and {num_edges} edges.")

    # Parse edge information
    # The .gph format starts node labeling with 1; we need 0 here, so we subtract one.
    split_edges = (line.split() for line in lines[1:])
    edges = [(int(u) - 1, int(v) - 1) for _, u, v in split_edges]

    return nx.Graph(edges)

graph_name = "es60fst02"
graph = fetch_qoblib_graph(graph_name)
Loading graph with 186 nodes and 280 edges.

Acest exemplu folosește instanța es60fst02 din QOBLIB, un graf cu 186 de noduri și 280 de muchii. Datorită pașilor de preprocesare folosiți de Constrained Quantum Optimizer, această instanță poate fi rezolvată pe dispozitive Heron cu 156 de qubiți. Graful poate fi vizualizat folosind matplotlib:

# Keep layout for later reuse

Construiește problema de optimizare​

Problema Maximum Independent Set poate fi formulată direct folosind OptimizationProblem. Fiecare nod al grafului devine o variabilă de decizie binară, iar fiecare muchie introduce o restricție care asigură că este selectat cel mult unul dintre capetele sale:

# Create an OptimizationProblem instance
mis_problem = OptimizationProblem("MIS")

# Add a binary variable for each node
x = mis_problem.binary_var_list(graph.number_of_nodes())

# Maximize the sum of all node variables
mis_problem.maximize(linear={xi.name: 1 for xi in x})

# Add '<= 1' constraints for each edge
for u, v in graph.edges:
    mis_problem.linear_constraint({x[u].name: 1, x[v].name: 1}, "<=", 1)

O scurtătură​

Pachetul qiskit-addon-opt-mapper oferă o clasă de aplicație preimplementată pentru problema Maximum Independent Set, care simplifică formularea de mai sus într-un singur apel:

mis = IndependentSet(graph)
mis_problem = mis.to_optimization_problem()

Pasul 3: Execută folosind primitivele Qiskit​

Fișierul LP poate fi acum trimis optimizatorului:

job = optimizer.run(model=lp_str, backend_name=backend.name)

print(f"Job ID: {job.job_id}")
Job ID: 87ec08b9-6275-40fa-be94-340a0a916bf1

Intern, algoritmul parcurge următoarele etape:

  1. Preprocessing:

    • Reduce variabilele fixabile

    • Găsește clici

    • Identifică tipurile de restricții

    • Evaluează factorii de penalizare pentru termenii de penalizare

    • Aplică transformările restricțiilor

    • Sintetizează circuitul folosind metode de impunere a restricțiilor

    • Aproximarea problemei și transpilare

  2. Lanțuri paralele de bucle iterative:

    • Eșantionează din circuit cu parametri fixați

    • Aplică postprocesarea

    • Evaluează și setează noi probabilități de warm-starting

  3. Postprocessing:

    • Găsește cele mai bune eșantioane și verifică fezabilitatea în raport cu problema de intrare

Anexă: Enunțul problemei cu Luna Model​

Pe lângă abordarea qiskit-addon-opt-mapper prezentată mai sus, Qiskit Function acceptă și modele create cu Luna Model [4], SDK-ul de modelare al Aqarios. După instalarea pachetului PyPI luna-model, importă-l după cum urmează:

Setup:

from luna_model import Model, Sense
import numpy as np

Modelul este apoi construit din graf în același mod ca la qiskit-addon-opt-mapper: Construiește modelul:

edges = np.array(graph.edges)

# Create the optimization model with a name
model = Model(name=f"MIS-{graph_name}", sense=Sense.MAX)
# Add binary variables
x = model.add_variables("x", graph.number_of_nodes())
# Set the objective
model.objective = x.sum()

# Use numpy like batch generation of constraints
model.add_constraints(x[edges].sum(axis=1) <= 1)

input_str = model.encode_b64()

# optimizer.run(model=input_str, backend_name="ibm_fez")
