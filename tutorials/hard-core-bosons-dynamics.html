Bosoni hard-core pe o rețea pătrată

Estimare de utilizare: aproximativ 2 minute de calcul clasic și niciun timp QPU, deoarece chipul este un backend simulat (Notă: aceasta este doar o estimare. Timpul tău de execuție poate varia.)

Acest tutorial prezintă qiskit-bosons, un cadru pentru explorarea fizicii bosonice pe calculatoare cuantice. Descrii un model bosonic o singură dată ca BosonOperator și BosonicCircuit, iar pachetul se ocupă de restul: un preset de Transpiler reduce circuitul la qubiți pentru trunchierea modurilor și codificarea nivelurilor pe care le alegi. Tutorialul folosește bosoni hard-core pe o rețea pătrată ca model exemplu. Fizica lor este suficient de simplă pentru a fi verificată față de o referință exactă, așa că te poți concentra pe cadrul în sine: construiești circuitul doar din dimensiunea rețelei, îl reduci la qubiți, îți măsori eroarea Trotter și costul și îl plasezi pe rețeaua pătrată a unui chip Nighthawk. Explorarea reală începe acolo unde se termină acest model, iar ultima secțiune arată primul pas dincolo de el.

Rezultate de învățare​

După parcurgerea acestui tutorial, te poți aștepta să înțelegi următoarele:

  • Cum este organizat qiskit-bosons: un model bosonic și circuitul său sunt scrise o singură dată, independent de trunchierea modurilor ddd și de codificarea nivelurilor, iar un preset de Transpiler le reduce la qubiți. Acest tutorial îl folosește pentru cel mai simplu caz, d=2d = 2d=2.
  • De ce bosonii hard-core sunt cazul d=2d = 2d=2, cum se raportează la modelul Bose-Hubbard și la fermionii liberi și de ce lanțul 1D este ușor din punct de vedere clasic, în timp ce rețeaua 2D nu este.
  • Cum se construiește hamiltonianul de salt pe o rețea pătrată ca BosonOperator grupat pe culori de muchii și circuitul de evoluție în timp al unui pas Trotter ca BosonicCircuit, independent de dimensiunea rețelei.
  • Cum reduce presetul de Transpiler qiskit-bosons acest circuit la qubiți pentru cele patru codificări de niveluri și de ce codurile compacte sunt cu un ordin de mărime mai ieftine decât cele unare la d=2d = 2d=2.
  • Cum se verifică circuitul față de o referință exactă și cum scade eroarea sa Trotter cu numărul de pași, pentru ordinul întâi și al doilea.
  • De ce încorporarea naturală a rețelei în rețeaua pătrată a unui chip Nighthawk nu necesită rutare, la orice dimensiune care încape pe chip.
  • Ce se schimbă când părăsești limita hard-core: același cadru descrie bosoni soft-core, dar costul crește rapid.

Schița acestui tutorial

  1. Modelul și fizica

  2. Construiește BosonicCircuit

  3. Calculează un quench Néel

  4. Cuantifică eroarea Trotter

  5. Scalează cu dimensiunea sistemului

  6. Transpilează pentru Nighthawk

  7. Dincolo de bosonii hard-core: trunchiere de moduri mai înaltă

  8. Concluzii și pașii următori

Dimensiuni: cele mai mari simulări exacte sunt rețele 4×44\times44×4 (16 qubiți); studiile de scalare merg până la 10×1210\times1210×12 (120 de qubiți, întregul chip Nighthawk).

def plain_log_ticks(axis, ticks, which="y"):
    """Log axis with plain tick labels (10, 20, 50 ...) instead of powers of ten."""
    formatter = plt.ScalarFormatter()
    getattr(axis, f"{which}axis").set_major_formatter(formatter)
    getattr(axis, f"set_{which}ticks")(ticks)
    getattr(axis, f"{which}axis").set_minor_formatter(plt.NullFormatter())

def plot_quench(times, panels, t_curves=T_CURVES):
    """The exact curves (lines) and the Trotterized circuit for several step lengths (dots), one panel per observable.

    `panels` maps a title to {"ylabel", "ylim", "exact": values at `times`, "circuit": {step length: values at its multiples}}.
    Pure plotting: nothing is computed here."""
    figure, axes = plt.subplots(
        1, len(panels), figsize=(14, 4), layout="constrained"
    )
    colors = dict(
        zip(
            sorted(next(iter(panels.values()))["circuit"], reverse=True),
            ("tab:red", "tab:orange", "tab:green"),
        )
    )
    for ax, (title, panel) in zip(axes, panels.items()):
        ax.plot(
            times,
            panel["exact"],
            "-",
            color="k",
            lw=2,
            label="exact (plain numpy)",
        )
        for dt, values in panel["circuit"].items():
            ax.plot(
                np.arange(len(values)) * dt,
                values,
                "o",
                ms=4,
                color=colors[dt],
                label=f"circuit, $dt = {dt}$ ({int(round(t_curves / dt))} steps)",
            )
        ax.set(
            xlabel="$t$ (units of $1/t_{hop}$)",
            ylabel=panel["ylabel"],
            title=title,
            ylim=panel["ylim"],
        )
        ax.grid(axis="y")
    axes[-1].legend(fontsize=8)
    plt.close(
        figure
    )  # drawn once, by being the cell's value; otherwise the inline backend shows it a second time
    return figure

def fitted_slope(rows, last=3):
    """Slope of log(max density error) against log(steps) over the last `last` points."""
    return float(
        np.polyfit(np.log(rows[-last:, 0]), np.log(rows[-last:, 1]), 1)[0]
    )

def curve_style(order, ordering=None):
    """(label, color, marker + line style).

    The bosonic circuit is a solid line with circles in the color of its order. A single gate is dashed with one marker per

def neel_bits(lx, ly):
    """Checkerboard occupation: site (x, y) holds one boson if x + y is even."""
    return [
        1 if (x + y) % 2 == 0 else 0 for y in range(ly) for x in range(lx)

def lattice_layout(lx, ly, width=WIDTH):
    """Virtual qubit -> physical qubit: site s = lx*y + x goes to qubit 10*y + x of the chip (width 10)."""
    return [width * y + x for y in range(ly) for x in range(lx)]

1. Modelul și fizica​

H=−t∑⟨ij⟩(bi†bj+bj†bi),(bi†)2=0.H = -t \sum_{\langle ij\rangle} \left(b_i^\dagger b_j + b_j^\dagger b_i\right), \qquad (b_i^\dagger)^2 = 0 .H=−t∑⟨ij⟩​(bi†​bj​+bj†​bi​),(bi†​)2=0.

În acest model, bosonii sar între siturile vecine ⟨ij⟩\langle ij\rangle⟨ij⟩ ale unei rețele pătrate. În principiu, un sit poate conține orice număr de bosoni; totuși, bosonilor hard-core le este interzis să împartă un sit. Astfel, fiecare sit conține zero sau un boson. În qiskit-bosons, aceasta se tratează prin trunchierea d=2d = 2d=2 (max_occupation = 1) în timpul mapării boson-la-qubit. def square_bonds(lx, ly):
    """Nearest-neighbor bonds (i, j) of an open lx x ly lattice, site s = lx * y + x."""
    bonds = []
    for y in range(ly):
        for x in range(lx):
            s = lx * y + x
            if x + 1 < lx:
                bonds.append((s, s + 1))
            if y + 1 < ly:
                bonds.append((s, s + lx))
    return bonds

def hardcore_dense(num_sites, bonds, tunneling=1.0):
    """Hard-core hopping as a matrix on bit strings: a boson hops when exactly one of the two sites is occupied."""
    dim = 2**num_sites
    h = np.zeros((dim, dim))
    for state in range(dim):
        for i, j in bonds:
            if ((state >> i) & 1) != ((state >> j) & 1):
                h[state ^ (1 << i) ^ (1 << j), state] += -tunneling
    return h

def free_fermion_matrix(num_sites, bonds, tunneling=1.0):
    """Free fermions on the same bonds, as a qubit matrix from qiskit-fermions' Jordan-Wigner mapper."""
    terms = {}
    for i, j in bonds:
        terms[(f_cre(i), f_ann(j))] = -tunneling
        terms[(f_cre(j), f_ann(i))] = -tunneling
    return (
        jordan_wigner(FermionOperator.from_dict(terms), num_sites)
        .simplify()
        .to_matrix()
    )

def spectrum_gap(num_sites, bonds):
    """Largest difference between the hard-core and the free-fermion eigenvalues over all particle-number sectors."""
    boson, fermion = (
        hardcore_dense(num_sites, bonds),
        free_fermion_matrix(num_sites, bonds),
    )
    popcount = np.array([bin(s).count("1") for s in range(2**num_sites)])
    gap = 0.0
    for n in range(1, num_sites):
        keep = popcount == n
        gap = max(
            gap,
            np.abs(
                np.linalg.eigvalsh(boson[np.ix_(keep, keep)])
                - np.linalg.eigvalsh(fermion[np.ix_(keep, keep)])
            ).max(),
        )
    return gap, bool(np.allclose(boson, fermion))

Un termen de salt este hermitian doar împreună cu perechea sa conjugată, deci ambii rămân într-un singur grup. Legăturile care nu au niciun sit comun comută, așa că o colorare a muchiilor rețelei pătrate dă grupuri care comută intern la nivel bosonic:

  • culoarea 2 / 3: legături verticale care încep la un rând par / impar (portocaliu și roșu)

Două legături de aceeași culoare nu au niciodată un sit comun, deoarece legăturile de-a lungul unei linii alternează culorile. def hardcore(lx, ly, tunneling=1.0):
    """Hard-core hopping on an open lx x ly lattice, grouped by edge color. Returns (operator, {bond: color})."""
    color_of = {
        (i, j): (i % lx) % 2 if j == i + 1 else 2 + (i // lx) % 2
        for i, j in square_bonds(lx, ly)
    }
    # group ids must be compact (a gap such as {0, 2} crashes the bosonic transpiler), so renumber the colors that occur
    remap = {c: k for k, c in enumerate(sorted(set(color_of.values())))}
    terms = []
    for (i, j), color in color_of.items():
        terms.append(([cre(i), ann(j)], -tunneling, remap[color]))
        terms.append(([cre(j), ann(i)], -tunneling, remap[color]))
    return BosonOperator.from_terms_with_groups(terms), color_of

def exact_hamiltonian(num_sites, bonds, tunneling=1.0):
    states = np.arange(2**num_sites, dtype=np.int64)
    rows, cols = [], []
    for i, j in bonds:
        differs = ((states >> i) & 1) != ((states >> j) & 1)
        source = states[differs]
        rows.append(source ^ ((1 << i) | (1 << j)))
        cols.append(source)
    rows, cols = np.concatenate(rows), np.concatenate(cols)
    return sp.csr_matrix(
        (np.full(len(rows), -tunneling), (rows, cols)),
        shape=(len(states),) * 2,
    )

def basis_state(bits):
    vector = np.zeros(2 ** len(bits), dtype=complex)
    vector[sum(b << i for i, b in enumerate(bits))] = 1.0
    return vector

def site_densities(state, num_sites):
    probabilities = np.abs(state) ** 2
    states = np.arange(len(state))
    return np.array(
        [
            probabilities[(states >> i) & 1 == 1].sum()
            for i in range(num_sites)
        ]
    )

def imbalance(density, lx, ly):
    sign = np.array([(-1) ** (x + y) for y in range(ly) for x in range(lx)])
    return float(np.mean(sign * (2 * density - 1)))

Pentru bosonii hard-core, operatorul pe qubiți este doar −12(XX+YY)-\tfrac12(XX + YY)−21​(XX+YY) pe legătură, deci îl poți da lui Qiskit și ca o singură PauliEvolutionGate, fără grupuri, și poți lăsa formula de produs SuzukiTrotter a lui Qiskit să îl împartă. O formulă de produs aplică termenii în ordinea în care sunt dați, deci ordinea decide care termeni sunt exponențiați împreună. Încearcă trei variante: termenii sortați după culoarea muchiei (gruparea pe care o cunoaște circuitul bosonic), termenii legătură cu legătură și preserve_order=False, care lasă Qiskit să reordoneze singur termenii.

def xx_yy_operator(lx, ly, by_color=True):
    """The qubit operator of the hard-core lattice, as plain Pauli terms: -1/2 (XX + YY) per bond, sorted by edge color or not."""
    color_of = hardcore(lx, ly)[1]
    bonds = (
        sorted(color_of, key=lambda bond: (color_of[bond], bond))
        if by_color
        else list(color_of)
    )
    terms = [
        (pauli, [i, j], -0.5) for i, j in bonds for pauli in ("XX", "YY")
    ]
    return SparsePauliOp.from_sparse_list(terms, num_qubits=lx * ly)

def single_gate(operator, order, time_=T_FINAL, steps=1, **formula):
    """ONE `PauliEvolutionGate` over the whole operator, synthesized with a product formula of the given order."""
    synthesis = SuzukiTrotter(order=order, reps=steps, **formula)
    circuit = QuantumCircuit(operator.num_qubits)
    circuit.append(
        PauliEvolutionGate(operator, time=time_, synthesis=synthesis),
        circuit.qubits,
    )
    return circuit

Stânga: liniile gri punctate sunt pantele ideale −1-1−1 și −2-2−2, iar panta ajustată pe ultimele trei puncte ale fiecărei curbe se află în legendă. Pantele se apropie de valorile ideale doar când pasul este suficient de mic; cu puțini pași, eroarea este în afara regimului asimptotic.

Dreapta: aceleași erori în funcție de adâncimea cu două qubiți a întregului circuit, pentru aceleași numere de pași. Un pas de ordinul doi are mai multe blocuri (14 față de 8 straturi pentru un pas), dar blocurile identice adiacente ale repetițiilor vecine fuzionează. Pentru erori mari (unu sau doi pași), ordinul întâi este modul mai ieftin de a atinge o eroare dată. Sub o eroare de aproximativ 10−110^{-1}10−1, ordinul doi este mai ieftin.

Porți unice. Curbele întrerupte sunt PauliEvolutionGate unică cu SuzukiTrotter de ordinul 1 (verde) și 2 (albastru). Fiecare ordonare a termenilor Pauli are propriul marcator și o nuanță mai deschisă a culorii. Cu termenii sortați după culoare (cruci), poarta unică se află exact pe curba bosonică de același ordin: este aceeași formulă de produs. În celelalte două ordonări, este o formulă diferită cu o eroare diferită, care poate fi de câteva ori mai mare sau (la unul sau doi pași) mai mică. Dar ordinul de mărime și scalarea coincid cu cele ale circuitului bosonic: curbele de ordinul întâi scad cu panta ideală −1-1−1, iar cele de ordinul doi cu −2-2−2, iar la 32 de pași toate cele trei ordonări se află într-un factor de aproximativ trei una față de alta. Deci eroarea Trotter nu decide între abordări. Ceea ce diferă este costul (panoul din dreapta și secțiunea următoare): la eroare egală, pătratele (nuanță medie) necesită o adâncime mult mai mare, iar triunghiurile (cea mai deschisă nuanță) aproximativ dublul adâncimii crucilor. La nivelul bosonic, gruparea face parte din operator, deci nu există nicio ordonare de ales manual, ceea ce duce la un flux de lucru mult mai ergonomic.

5. Scalează cu dimensiunea sistemului​

Această secțiune investighează cum scalează costul cu dimensiunea rețelei. Deoarece un pas Trotter înseamnă un strat XX+YYXX+YYXX+YY pe culoare, indiferent de numărul de situri, adâncimea cu două qubiți ar trebui să fie constantă în raport cu dimensiunea rețelei, în timp ce numărul de porți crește odată cu numărul de legături. Dimensiunile ajung până la 10×1210\times1210×12, întregul cip Nighthawk în codurile compacte. Codurile unare necesită doi qubiți pe mod, deci se opresc la dimensiunile care încap în 120 de qubiți.

Codul compact are o adâncime constantă începând de la 3×33\times33×3 (fiecare culoare este un strat de rotații XX+YYXX+YYXX+YY alăturate; rețeaua 2×22\times22×2 are doar două culori, deci adâncimea ei este jumătate) și un număr de porți care crește cu numărul de legături. Codurile unare sunt cu un ordin de mărime mai costisitoare în ambele privințe. Motivul este simplu: în codurile compacte, o legătură se mapează la un termen XXXXXX și unul YYYYYY pe cei doi qubiți ai legăturii, cu coeficienți egali, adică o rotație XX+YYXX+YYXX+YY (două cz). În codurile unare, fiecare mod are doi qubiți (unul pe nivel), iar saltul se extinde în mai multe șiruri Pauli de pondere 4 pe cei patru qubiți ai ambelor moduri. Toate comută, deci nu se economisește nimic prin comutare. Raportul este o proprietate a codificării la d=2d = 2d=2 și nu se schimbă cu dimensiunea rețelei. La d=2d = 2d=2, codurile binar standard și Gray sunt același cod, iar codurile unare proiectat și neproiectat emit același operator, deci curba compactă reprezintă ambele perechi. De ce să aplici Trotter la nivel bosonic? Curbele întrerupte sunt aceiași pași Trotter ca o singură PauliEvolutionGate peste operatorul pe qubiți (secțiunea 4), cu verde pentru ordinul întâi și albastru pentru ordinul doi. Curba albastră continuă este circuitul bosonic de ordinul doi, iar curba verde continuă cea de ordinul întâi de mai sus. Poarta unică cu termenii sortați după culoare (cruci) se află exact pe curba bosonică de ordinul ei: adâncime constantă (8 pentru ordinul întâi, 14 pentru ordinul doi) și numărul minim de porți (ca în secțiunea anterioară). Qiskit nu găsește singur această grupare. Dacă termenii sunt listați legătură cu legătură (pătrate), numărul de porți este același, dar straturile nu sunt compactate, iar adâncimea crește odată cu rețeaua (la 10×1210\times1210×12 este 84 față de 8 pentru ordinul întâi și 166 față de 14 pentru ordinul doi). Cu preserve_order=False (triunghiuri), Qiskit găsește termeni care comută, iar adâncimea rămâne constantă, dar tratează termenul XX și termenul YY al unei legături ca rotații separate, deci are nevoie de cu aproximativ o treime mai multe porți cu doi qubiți și de dublul adâncimii. Așadar nivelul bosonic nu este magie: poartă colorarea muchiilor în operatorul însuși, iar ceea ce altfel ar trebui aranjat manual în termenii Pauli (și menținut aranjat pentru fiecare rețea) vine odată cu construcția.

7. Dincolo de bosonii hard-core: trunchiere de mod mai mare​

Tot ce am văzut până acum a considerat doar bosoni hard-core, deci termenul pe sit nu putea acționa. Cu d=3d = 3d=3, un sit poate conține doi bosoni, U2n(n−1)\tfrac U2 n(n-1)2U​n(n−1) apare ca al treilea grup (diagonal), iar elementele de matrice ale saltului capătă factori 2\sqrt22​. Celula următoare construiește pasul Bose-Hubbard pe un lanț de 4 situri și îi măsoară costul în același mod, pentru toate cele patru codificări, alături de lanțul hard-core de aceeași lungime.

def bose_hubbard(num_sites, tunneling=1.0, interaction=2.0):
    """Grouped Bose-Hubbard Hamiltonian on an open chain: group 0 = even bonds, 1 = odd bonds, 2 = on-site."""
    edges = [(i, i + 1) for i in range(num_sites - 1)]
    terms = {}
    for i, j in edges:
        terms[(cre(i), ann(j))] = -tunneling
        terms[(cre(j), ann(i))] = -tunneling
    for i in range(num_sites):
        terms[(cre(i), cre(i), ann(i), ann(i))] = 0.5 * interaction
    operator = BosonOperator.from_dict(terms)

    def group_of(actions):
        creations = sorted(m for a, m in actions if a)
        annihilations = sorted(m for a, m in actions if not a)
        if creations == annihilations:
            return 2
        return (
            edges.index(tuple(sorted(set(creations) | set(annihilations))))
            % 2
        )

    raw = [group_of(actions) for actions, _ in operator.iter_terms()]
    remap = {g: i for i, g in enumerate(sorted(set(raw)))}
    operator.groups = [remap[g] for g in raw]
    return operator

Din aceste numere poți trage câteva concluzii generale. Primele privesc cadrul de lucru, pe care îl transferi la alte modele bosonice. Cele de după privesc ce arată rezultatele pentru bosonii hard-core, cazul simplu de test.

  • Un cadru pentru fizica bosonică. qiskit-bosons separă trei lucruri: modelul (un BosonOperator, grupat aici după culoarea muchiei), circuitul (o poartă Evolution și o formulă Trotter care o împarte) și coborârea la qubiți (trunchierea de mod ddd și LevelEncoding, alese când rulează presetul transpiler-ului). Schimbarea unuia dintre ele le lasă neatinse pe celelalte două (secțiunile 2 și 7).

  • De ce să aplici Trotter la nivel bosonic. Gruparea se află în operator, deci circuitul Trotter rezultă cu adâncime constantă, fără nicio ordonare manuală. O singură PauliEvolutionGate peste același operator pe qubiți are același ordin al erorii Trotter și aceeași scalare, iar cu termenii sortați după culoare este circuitul identic. Într-o altă ordine, adâncimea crește odată cu rețeaua (84 față de 8 pentru un pas de ordinul întâi la 10×1210\times1210×12) sau numărul de porți este cu aproximativ o treime mai mare (secțiunile 4 și 5).

  • Acuratețe. Singura eroare numerică este eroarea Trotter dintre culori, iar ea scade cu numărul de pași conform așteptărilor pentru ordinul întâi și doi (secțiunea 4). Partea de qubiți și codificarea nu adaugă nimic.

  • Codificarea este o alegere de cost. La d=2d = 2d=2, toate cele patru codificări dau aceeași fizică. Codurile compacte necesită jumătate din qubiți și sunt de aproximativ 20 de ori mai ieftine ca adâncime și porți decât cele unare (secțiunea 5).

  • Hardware. Cu încorporarea naturală a rețelei, fiecare poartă se află deja pe un cuplor Nighthawk, deci cipul rulează circuitul fără cheltuieli de rutare la orice dimensiune, până la întregul cip (secțiunea 6).

  • Bosonii hard-core sunt punctul de intrare, nu scopul. Sunt limita U→∞U\to\inftyU→∞ a modelului Bose-Hubbard, cu modelul XY ca echivalent de spin 1/2. Sunt exact fermioni liberi pe un lanț deschis, dar nu pe o rețea pătrată, ceea ce face din 2D cazul interesant (secțiunea 1). Creșterea trunchierii la d=3d = 3d=3 readuce interacțiunea pe sit, iar costul crește brusc (un lanț de 4 situri trece de la o adâncime cu doi qubiți de 4 la 95 în codul Gray, secțiunea 7). Aici începe explorarea fizicii bosonice, iar același cadru o susține. Atenționări. Toate adâncimile sunt pentru un backend simulat fără zgomot (FakeNighthawk) și o bază fixă (cz, rz, sx, x, nivel de optimizare 3); compară structura, nu fidelitatea. Numerele rutate sunt egale cu cele abstracte doar pentru că încorporarea naturală pune fiecare poartă pe un cuplor. Quench-ul Néel este o singură stare inițială; eroarea Trotter depinde de stare și de TTT. Nimic de aici nu rulează pe hardware real.

Pașii următori. Bosonii hard-core sunt un model simplu, verificabil, pe care poți învăța cadrul de lucru. De aici, aceleași blocuri de construcție se aplică modelelor greu de tratat clasic:

  • Limite ddd mai mari (bosoni soft-core, modelul Bose-Hubbard complet), unde alegerea codificării și a formulei Trotter contează mult mai mult decât aici (secțiunea 7)

  • Alți hamiltonieni, cum ar fi bosoni cu o interacțiune diferită sau cu un cuplaj diferit la mediul lor

  • Alte rețele, cum ar fi cea triunghiulară sau fagure, care necesită alte colorări ale muchiilor și alte încorporări hardware

  • Funcții de corelație ca observabile, cum ar fi ⟨XiXj+YiYj⟩\langle X_iX_j + Y_iY_j\rangle⟨Xi​Xj​+Yi​Yj​⟩ și corelatori densitate-densitate

  • Modele mixte (bosoni cuplați la fermioni sau la o baie)
