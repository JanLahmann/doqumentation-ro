Unelte pentru profilarea, personalizarea și inspectarea experimentelor

Estimare de utilizare: 10 minute pe un procesor Heron r2 (NOTĂ: aceasta este doar o estimare. Timpul tău de rulare poate varia.)

Pentru a obține rezultate bune de la un computer cuantic, ai nevoie de mai mult decât un circuit bine proiectat. Starea curentă a dispozitivului, modul în care este programat circuitul, zgomotul pe care îl întâmpină circuitul și momentul și modul în care rulează jobul tău pe unitatea de procesare cuantică (QPU) influențează toate calitatea rezultatelor. Qiskit și IBM Quantum® Compute Service oferă un set tot mai mare de unelte pentru dezvoltatori care expun aceste informații. Poți folosi aceste unelte pentru a acționa pe baza informațiilor înainte de a angaja timp QPU pentru un experiment complet și pentru a depana un experiment încheiat.

Acest tutorial folosește un singur experiment cap-coadă pentru a arăta cum să combini aceste unelte la fiecare etapă a unui flux de dezvoltare tipic. Nu fiecare unealtă este utilă pentru fiecare experiment, așa că alege uneltele care răspund întrebărilor pe care le ai despre propria ta sarcină.

Fluxul de lucru este următorul:

  1. Pregătește un circuit-oglindă al unei evoluții în timp Trotter a unui model Ising liniar cu câmp transversal.

  2. Selectează un backend cu un set alternativ de date de calibrare, proiectat pentru metode de atenuare a erorilor bazate pe un model de zgomot.

  3. Rulează experimente de benchmarking al dispozitivului, astfel încât transpiler-ul să folosească proprietăți actualizate ale dispozitivului când alege un layout.

  4. Inspectează informațiile de temporizare ale circuitului programat.

  5. Învață modele de zgomot Pauli-Lindblad și de citire pentru circuit.

  6. Rulează simulări locale fără zgomot, fără atenuare și cu atenuare. Simulările cu zgomot folosesc modelul de zgomot învățat pentru a arăta cât de mult te-ai putea îmbunătăți prin metodele de atenuare a erorilor alese. Acest tutorial folosește anularea probabilistică a erorilor (PEC) și Twirled Readout Error eXtinction (TREX).

  7. Obține o estimare de utilizare fără a rula pe un QPU, pentru a verifica dacă trebuie să ajustezi experimentul ca să se încadreze în buget.

  8. Pornește o sesiune și declanșează calibrarea, astfel încât experimentul să folosească cele mai recente date de calibrare.

  9. Rulează experimentul pe QPU folosind Estimator și compară rezultatele hardware cu previzualizarea simulată.

  10. Inspectează execution spans pentru a vedea dacă există goluri semnificative între grupuri de execuții (chunk-uri).

Cerințe​

Înainte de a începe acest tutorial, asigură-te că ai instalate următoarele:

  • Qiskit SDK v2.3 sau mai nou, cu suport pentru vizualizare

  • qiskit-ibm-runtime v0.52.1 or later (pip install qiskit-ibm-runtime)

  • Qiskit Aer (pip install qiskit-aer)

  • Plotly (pip install plotly)

  • Qiskit Device Benchmarking (pip install git+https://github.com/qiskit-community/qiskit-device-benchmarking.git)

Cerințe de plan

Unii pași din acest tutorial nu sunt disponibili pe toate planurile:

  • Joburile dry-run (Pașii 2.4 și 3.5) sunt disponibile doar pe planurile Flex, Premium și On-Prem.

  • Sesiunile (Pasul 4.1) nu sunt disponibile pe planul Open. Pentru a rula în schimb în batch mode, setează run_calibration = False în Pasul 4.1.

Pasul 1: Specifică un circuit și o observabilă​

Pregătește un circuit-oglindă al unei evoluții în timp Trotter a unui model Ising liniar cu câmp transversal. Oglindește circuitul pentru a anula unitarul circuitului și a forma un circuit identitate. Deoarece ieșirea ideală este starea cu toți qubiții în zero, valoarea medie ideală a fiecărei observabile ZZZ pe un singur qubit este 1. Oglindirea dublează și adâncimea circuitului, ceea ce amplifică efectul zgomotului.

import numpy as np
from qiskit.circuit import QuantumCircuit
from qiskit.quantum_info import SparsePauliOp

def construct_ising_circuit(
    num_qubits: int,
    num_trotter_steps: int,
    rx_angle: float,
    barrier: bool = True,
) -> QuantumCircuit:
    circuit = QuantumCircuit(num_qubits)

    for _step in range(num_trotter_steps):
        circuit.rx(rx_angle, range(num_qubits))
        if barrier:
            circuit.barrier()
        for first_qubit in (1, 2):
            for idx in range(first_qubit, num_qubits, 2):
                # equivalent to Rzz(-pi/2):
                circuit.sdg([idx - 1, idx])
                circuit.cz(idx - 1, idx)
        if barrier:
            circuit.barrier()

    return circuit

def mirror_circuit(circuit: QuantumCircuit) -> QuantumCircuit:
    mirror_circ = circuit.copy_empty_like()
    mirror_circ.compose(circuit, inplace=True)
    mirror_circ.barrier()
    mirror_circ.compose(circuit.inverse(), inplace=True)
    mirror_circ.measure_active()
    return mirror_circ
num_qubits = 20
observables = [
    SparsePauliOp("I" * ((num_qubits - 1) - q) + "Z" + "I" * q)
    for q in range(num_qubits)
]

# Free parameters of the demonstration circuit: the number of Trotter steps
# sets the circuit depth, and rx_angle is the transverse-field rotation angle
# applied in each step (pi/4 makes the dynamics non-Clifford)
num_trotter_steps = 5
rx_angle = np.pi / 4

circuit = construct_ising_circuit(
    num_qubits, num_trotter_steps, rx_angle, barrier=False
)
mirrored_circuit = mirror_circuit(circuit)
mirrored_circuit.draw(
    "mpl", fold=-1, scale=0.3, idle_wires=False, measure_arrows=False
)

Pasul 2: Optimizează pentru execuția pe hardware cuantic​

2.1 Folosește calibrarea alternativă, dacă este cazul​

IBM® își calibrează periodic QPU-urile pentru performanță bună în cazurile generale de utilizare. Unele sarcini, însă, beneficiază de instrucțiuni ai căror parametri sunt reglați diferit. Pentru mai multe informații, consultă Instrucțiuni calibrate special.

Acest tutorial folosește un set alternativ de date de calibrare numit slow_gates_ac. Această calibrare conține o poartă cz mai lentă și modulează polarizarea sistemului cu două niveluri (TLS) pentru a stabiliza erorile dispozitivului în timp. Aceste modificări avantajează metodele de atenuare a erorilor care se bazează pe un model de zgomot învățat. Calibrarea slow_gates_ac este disponibilă doar pe QPU-uri Heron. Dacă rulezi pe un QPU Nighthawk, folosește în schimb slow_gates.

from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()
# Use slow_gates_ac because this tutorial uses a noise-learning-based mitigation method
backend = service.backend("ibm_kingston", calibration_id="slow_gates_ac")

2.2 Rulează benchmarking în timp real al dispozitivului​

Una dintre cele mai critice etape ale transpilării este selecția layout-ului, care mapează qubiții virtuali ai unui circuit pe qubiți fizici ai dispozitivului țintă. Un layout bun minimizează numărul de operații SWAP necesare și plasează circuitul pe qubiții cu cele mai bune performanțe, deci calitatea layout-ului inițial poate afecta semnificativ calitatea rezultatelor tale.

Rutine periodice de benchmarking rulează pe fiecare QPU IBM pentru a raporta performanța curentă a qubiților săi: timpi de relaxare (T1T_1T1​), timpi de coerență (T2T_2T2​), erori de citire și erori ale porților pe unul și doi qubiți. Transpiler-ul Qiskit folosește aceste metrici în timpul selecției layout-ului.

Proprietățile qubiților supraconductori pot totuși deriva pe scale de timp mai scurte, iar defectele tranzitorii, cunoscute ca TLS-uri, pot degrada temporar un qubit care se comporta bine la momentul calibrării. Dacă transpiler-ul folosește informații depășite, nu poate alege cel mai bun layout. De aceea, poate merita să cheltuiești puțin timp QPU pentru a caracteriza dispozitivul înainte de a alege un layout.

Consultă tutorialul Reîmprospătarea proprietăților backend-ului cu benchmarking în timp real pentru o prezentare detaliată. Suita de caracterizare construiește mai multe experimente, trimite mai multe joburi și potrivește rezultatele. Acest proces poate dura câteva minute în total. Activează jurnalizarea la nivel INFO pentru ca fiecare etapă să-și afișeze progresul pe măsură ce rulează.

import sys
import logging

logger = logging.getLogger("qiskit_device_benchmarking")
logger.setLevel(logging.INFO)
logger.addHandler(logging.StreamHandler(stream=sys.stdout))

2.4 Vizualizează temporizarea circuitului​

Pe lângă instrucțiunile dintr-un circuit, poate vrei să vizualizezi planificarea circuitului, pentru a găsi timpii morți ai qubiților sau alinierea ineficientă a instrucțiunilor. Cele mai detaliate și precise informații de temporizare le poți obține de la IBM Quantum Compute Service folosind modul dry-run.

Circuitul din acest tutorial este static, deci planificarea lui nu este foarte informativă. Poți obține informații de temporizare similare local, din circuit și din proprietățile backend-ului, de exemplu folosind timeline drawer integrat în Qiskit. Acest tutorial include acest pas pentru a arăta cum să soliciți și să vizualizezi informațiile de temporizare. Informațiile de temporizare de la serviciu sunt cele mai utile pentru circuite dinamice. Circuitele dinamice conțin măsurători la mijlocul circuitului, operații condiționale și feedforward, care adaugă operații implicite, precum difuzarea rezultatelor măsurătorilor și determinarea ramurilor. Temporizarea acestor operații nu poate fi determinată doar din circuit și din proprietățile backend-ului.

Consultă Vizualizarea temporizării circuitului pentru mai multe informații. Temporizarea circuitului planificat este disponibilă doar pentru joburile Sampler și Executor, așa că celula următoare trimite circuitul în modul dry-run folosind Sampler. Joburile pe care le trimiți în modul dry-run nu rulează pe QPU-uri reale și nu sunt taxate.

from qiskit_ibm_runtime.executor_sampler import Sampler

Pasul 3: Aplică atenuarea erorilor și testează local​

3.1 Cliffordizează circuitul​

Costul simulării zgomotoase generale crește exponențial cu numărul de qubiți, iar majoritatea laptopurilor nu pot simula mai mult de aproximativ 32 de qubiți. Prin urmare, convertește mai întâi circuitul într-un circuit Clifford, pe care un simulator de stabilizatori îl poate gestiona mult mai eficient. Conversia rotunjește fiecare unghi de rotație la un unghi Clifford, astfel încât circuitul simulat aproximează circuitul original, în loc să îl reproducă.

from qiskit.transpiler import PassManager
from qiskit_ibm_runtime.transpiler.passes import ConvertISAToClifford

clifford_circuit = PassManager([ConvertISAToClifford()]).run(isa_circuit)
clifford_pubs = [(clifford_circuit, isa_observables)]

3.2 Aplică PEC cu TREX​

Poate fi dificil să alegi metode de atenuare a erorilor care echilibrează costul și acuratețea pentru experimentul tău specific. Poți folosi skill-ul de agent AI select-error-mitigation pentru a analiza metodele disponibile pentru sarcina ta. Skill-ul prezintă un raport rezumat care explică dacă fiecare metodă a fost selectată și de ce.

Consultă depozitul GitHub Qiskit AI skills pentru mai multe informații. Acest tutorial folosește PEC cu TREX direct, astfel încât să îl poți parcurge fără un agent AI.

PEC este o tehnică ce atenuează zgomotul cuantic atunci când calculezi valorile de așteptare ale observabilelor. În condiții ideale, PEC poate produce o estimare nedeplasată a valorilor de așteptare. Ea învață zgomotul fiecărui strat de porți cu doi qubiți, apoi rulează un ansamblu de circuite care, în medie, aplică inversul acelui zgomot. PEC folosește Pauli twirling pentru a adapta zgomotul într-un canal Pauli, care poate fi învățat și inversat eficient.

În practică, PEC este exact atât de precis cât este modelul de zgomot învățat. Modelul Pauli-Lindblad rar include doar termeni de eroare cu unul și doi qubiți pe qubiți vecini și nu poate surprinde complet efecte precum diafonia dintre qubiți îndepărtați sau erorile corelate în timp. Zgomotul dispozitivului poate, de asemenea, să derapeze între învățarea zgomotului și execuție. PEC nu anulează zgomotul pe care modelul îl ratează și supracompensează zgomotul pe care modelul îl supraestimează. Prin urmare, rezultatele atenuate pot totuși să se abată de la valorile ideale în oricare direcție.

TREX este o tehnică ce atenuează erorile de măsurare și este utilă atunci când estimezi valorile de așteptare ale observabilelor Pauli. Se bazează pe measurement twirling, care diagonalizează matricea de transfer a erorilor de citire și o face ușor de inversat. TREX învață un termen de rescalare din canalul de zgomot diagonal măsurând circuite de calibrare twirled inițializate în starea zero. Poți activa atât PEC, cât și TREX setând opțiunile Estimator. Acest tutorial folosește implementările pe partea clientului ale interfețelor Qiskit SamplerV2 și EstimatorV2, introduse în qiskit-ibm-runtime v0.50.0. Aceste primitive pe partea clientului efectuează local cea mai mare parte a pre- și post-procesării și deleagă execuția primitivei Executor. Când primitivele rulează pe partea clientului, obții o transparență mai mare, feedback mai rapid la depanare și control mai fin.

Primitivele pe partea clientului implementează același API ca primitivele vechi de pe partea serverului. Prin urmare, de obicei poți trece la primitivele pe partea clientului schimbând doar instrucțiunea de import. Activează logarea la nivel INFO pentru a vedea progresul pre- și post-procesării pe partea clientului.

import logging

logger = logging.getLogger("qiskit_ibm_runtime")
logger.setLevel(logging.INFO)
from qiskit_ibm_runtime.executor_estimator import Estimator

estimator = Estimator(mode=backend)
# Enable TREX
estimator.options.resilience.measure_mitigation = True
# Enable PEC
estimator.options.resilience.pec_mitigation = True

3.3 Învață modelele de zgomot și rulează circuitul cliffordizat​

Atât PEC, cât și TREX necesită învățarea zgomotului, pe care o poți face cu NoiseLearnerV3. Pașii sunt următorii:

  1. Găsește straturile unice de porți cu doi qubiți și straturile de măsurare din circuit, pentru protocoalele Pauli-Lindblad și, respectiv, TREX.

  2. Transmite straturile către NoiseLearnerV3 pentru a învăța modelele de zgomot.

  3. Convertește modelele de zgomot învățate în hărți Pauli-Lindblad.

Estimator nu folosește un model de zgomot TREX învățat în prealabil. În schimb, își efectuează propria învățare TREX. Codul următor învață oricum ambele modele, deoarece simularea zgomotoasă folosește modelul de citire învățat.

Consultă Noise learning helper pentru mai multe informații despre NoiseLearnerV3. Pe lângă experimentul de învățare a zgomotului, rulează circuitul cliffordizat pe QPU. Acest pas nu este întotdeauna necesar, dar oferă o comparație pentru rezultatele simulate din Pasul 3.4.4. Rulează-le pe ambele într-un batch pentru a minimiza cât derapează profilul de zgomot între cele două.

pubs = [(isa_circuit, isa_observables)]
# Specify types="all" to find layers for both Pauli-Lindblad and TREX learning
layers = estimator.find_unique_layers(pubs, types="all")

4.1 Inițializează o sesiune și rulează calibrarea​

Calibrarea QPU optimizează mulți parametri care definesc semnalele electrice ce controlează porțile și operațiile cuantice. Joburile de calibrare rulează pe parcursul zilei între joburile utilizatorilor, dar nu în timpul unei sesiuni active. Acești parametri pot deriva într-un interval scurt de timp. Pentru cele mai bune rezultate posibile, ia în considerare declanșarea calibrării la începutul unei sesiuni sau periodic în timpul unei sesiuni de lungă durată.

În prezent, este acceptată doar calibrarea citirii, iar aceasta durează aproximativ cinci minute de timp real (wall-clock).

Reprezintă grafic rezultatele hardware atenuate și neatenuate împreună cu valorile ideale. Deoarece circuitul este un circuit oglindă, fiecare valoare ideală este 1, deci distanța dintre fiecare punct și linia punctată arată eroarea rămasă. Pentru a îmbunătăți și mai mult rezultatele, poți încerca următoarele:

  • Mărește numărul de shots sau de randomizări pentru a reduce incertitudinea statistică a estimărilor atenuate. Costul crește odată cu overhead-ul de eșantionare PEC.

  • Reînvață modelul de zgomot imediat înainte de experiment, în aceeași sesiune, pentru a reduce efectul derivei zgomotului.

  • Învață modelul de zgomot mai precis mărind opțiunile num_randomizations, shots_per_randomization sau layer_pair_depths ale NoiseLearnerV3. Erorile din ratele învățate introduc o deplasare în rezultatele atenuate, iar shots PEC suplimentare nu elimină această deplasare.

Apoi elimină acele shots prin postselecție. Aplică aceleași verificări când înveți modelul de zgomot, folosind opțiunile bit_flip_checks ale NoiseLearnerV3. Altfel, modelul învățat include erori pe care postselecția le elimină din experiment, iar PEC le supracompensează. O postselecție mai strictă elimină mai multe shots, așa că echilibrează câștigul de acuratețe cu numărul de shots pe care îl păstrezi.

        print(f"{title:<36} {label:<24} mean absolute deviation: {error:.3f}")

În această rulare, atenuarea a redus abaterea absolută medie de la 0,290 la 0,046 în simulare (aproximativ de șase ori) și de la 0,202 la 0,050 pe QPU (aproximativ de patru ori). În ambele cazuri, valorile atenuate sunt împrăștiate în jurul valorii 1, iar cele mai multe dintre ele concordă cu 1 în limitele barelor lor de eroare.

4.4 Inspectează execution spans​

Când trimiți circuite cu mai multe configurații, de exemplu cu gate twirling, IBM Quantum Compute Service nu rulează neapărat toate configurațiile circuitului în același timp. În schimb, le grupează în bucăți (chunks) și rulează o bucată pe fiecare shot loop. Un shot loop este o singură rundă de execuție pe hardware-ul cuantic, în care fiecare circuit din bucată este rulat pentru numărul solicitat de shots.

Toate joburile trimise către un QPU real necesită o anumită pre-procesare clasică, precum traducerea în pulsuri care pot fi trimise către hardware. Deoarece această pre-procesare se poate face în paralel, serviciul scoate din coadă și pornește mai multe joburi simultan. QPU-ul, însă, poate procesa o singură unitate de lucru la un moment dat. Prin urmare, dacă jobul tău generează mai multe bucăți, acestea pot fi intercalate cu bucățile joburilor altor utilizatori, iar fiecare bucată poate trebui să-și aștepte rândul pe QPU.

Metadatele rezultatului jobului raportează temporizarea execuției pe QPU pentru fiecare bucată. Vizualizarea următoare arată dacă există goluri semnificative între execuțiile bucăților din jobul tău. Dacă golurile sunt mai mari decât poate tolera experimentul tău, poate vrei să rulezi din nou jobul sau să folosești modul de execuție session, care oferă sarcinii tale acces exclusiv la QPU.

Pașii următori​

Recomandări
  • Rulează din nou experimentul cu și fără calibrarea slow_gates_ac (Pasul 2.1), proprietățile reîmprospătate ale dispozitivului (Pasul 2.2) sau calibrarea sesiunii (Pasul 4.1) pentru a măsura cât de mult îmbunătățește fiecare instrument rezultatele pentru sarcina ta.
  • Încearcă o metodă de atenuare a erorilor mai ieftină, precum extrapolarea la zero zgomot (ZNE), și folosește simularea locală și estimările de utilizare dry-run pentru a-i compara costul și acuratețea cu cele ale PEC. Skill-ul de agent AI select-error-mitigation te poate ajuta să faci această alegere.
  • Explorează suita completă de caracterizare, inclusiv randomized benchmarking, în tutorialul Reîmprospătează proprietățile backend-ului cu benchmarking în timp real.
  • Află mai multe despre primitivele pe partea clientului și despre Executor în Migrarea de la Sampler și Estimator pe partea serverului la cele pe partea clientului.
  • Aplică aceste instrumente propriilor experimente. Începe cu instrumentele care abordează cea mai mare sursă de incertitudine, precum calitatea dispozitivului, zgomotul, costul sau temporizarea execuției.
