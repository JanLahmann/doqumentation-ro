Configurează QCSC-Prefect pe un cluster Slurm

Acest ghid pregătește nodul de login al unui cluster Slurm drept gazdă de workflow pentru qcsc-prefect. Tutorialul qcsc-prefect SQD pornește de la rezultatul acestui ghid.

După ce parcurgi acest ghid, vei avea următoarele elemente:

ElementUndeConținut
~/venv/qcsc-hostNodul de login, gazda de workflowPrefect, pachetele qcsc-prefect și comanda qcsc-qrmi
~/venv/qcsc-nodeNodurile de calcul, în joburile SlurmWorker-ul QRMI: QRMI cu comanda sa task_runner și qcsc-prefect-qiskit
qrmi-runtimePrefectBlocul care denumește instanța ta IBM Quantum® și QPU-ul
qrmi_config.jsonNodul de login și nodurile de calculCheia ta API IBM Cloud®, instanțele și Backend-urile pentru QRMI

Rulează fiecare comandă într-un terminal pe nodul de login, cu excepția cazului în care pasul spune altfel.

Cerințe preliminare​

  • Un cluster Slurm cu OpenMPI, PMIx și pluginul QRMI SPANK, pe care le instalează administratorul clusterului. Următoarele ghiduri descriu aceste componente:

    • Quantum resource management interface (QRMI)

    • Plugin SPANK pentru QRMI

    • Ghid de utilizare pentru pluginul SPANK

  • Un director home și un director de lucru pe care nodul de login și nodurile de calcul le văd la aceleași căi absolute

  • Acces HTTPS de ieșire către GitHub, PyPI, IBM Quantum și Prefect Cloud de pe nodul de login și către IBM Quantum de pe nodurile de calcul

  • Un cont IBM Quantum Platform cu o cheie API IBM Cloud și cel puțin o instanță

  • Un cont Prefect Cloud sau un server Prefect pe care îl găzduiești tu

  • Git, compilatoare C și C++, CMake, BLAS, LAPACK și MPI pe cluster, pentru build-urile solverelor din tutorial

notă

Exemplele folosesc partiția Slurm normal și nodurile de calcul c1 și c2. Înlocuiește-le cu numele din clusterul tău.

Pasul 1: Conectează-te la nodul de login​

# Run in a terminal on your computer.
ssh <user>@<login-node>

Pasul 2: Instalează uv​

Instalează managerul de pachete uv și verifică instalarea:

curl -LsSf https://astral.sh/uv/install.sh | sh
source "$HOME/.local/bin/env"
uv --version

Pasul 3: Setează căile și creează directorul de lucru​

Acest ghid și tutorialele folosesc două variabile de mediu:

VariabilăExempluScop
QCSC_PREFECT$HOME/qcsc-prefectCheckout-ul qcsc-prefect
QCSC_WORK_DIR/shared/work/qcsc-prefectDirectorul de lucru al joburilor solverului și al joburilor QRMI

Ambele căi trebuie să fie pe un spațiu de stocare pe care nodurile de calcul îl văd la aceeași cale absolută. Dacă clusterul tău nu are un director /shared, alege altă cale partajată.

Setează variabilele și creează directorul de lucru. Setează din nou variabilele în fiecare shell nou inainte de a urma un tutorial:

export QCSC_PREFECT="$HOME/qcsc-prefect"
export QCSC_WORK_DIR=/shared/work/qcsc-prefect
mkdir -p "$QCSC_WORK_DIR"

Pentru a seta variabilele automat în fiecare shell nou, adaugă-le în ~/.bashrc:

# Optional
echo "export QCSC_PREFECT=$QCSC_PREFECT" >> ~/.bashrc
echo "export QCSC_WORK_DIR=$QCSC_WORK_DIR" >> ~/.bashrc

Pasul 4: Clonează qcsc-prefect​

Clonează depozitul și fă checkout la un tag de versiune, de exemplu v0.3.1:

git clone https://github.com/qiskit-community/qcsc-prefect.git "$QCSC_PREFECT"
cd "$QCSC_PREFECT"
git checkout v0.3.1

Pasul 5: Creează mediul de workflow​

Creează mediul de workflow cu Python 3.12 și activează-l:

uv venv ~/venv/qcsc-host -p 3.12
source ~/venv/qcsc-host/bin/activate

Instalează pachetele qcsc-prefect. Opțiunea --no-deps păstrează exact versiunile fixate între pachetele din checkout. Tutorialul instalează chiar fluxul de lucru:

cd "$QCSC_PREFECT"
uv pip install --no-deps \
  -e packages/qcsc-prefect-core -e packages/qcsc-prefect-adapters \
  -e packages/qcsc-prefect-blocks -e packages/qcsc-prefect-executor \
  -e 'packages/qcsc-prefect-qiskit[slurm]'

Verifică dacă comenzile sunt disponibile:

which prefect qcsc-qrmi

Activează ~/venv/qcsc-host în fiecare shell nou de pe nodul de login.

Pasul 6: Autentifică-te în Prefect​

Autentifică-te în Prefect Cloud. Alege Paste an API key, lipește o cheie API Prefect Cloud și alege spațiul tău de lucru:

prefect cloud login

Verifică conexiunea. Rezultatul afișează PREFECT_API_URL și spațiul tău de lucru:

prefect config view
Opțional: folosește propriul server Prefect

Sari peste această notă dacă folosești Prefect Cloud. Pentru a folosi propriul server Prefect în loc de Prefect Cloud, urmează How to run and access a Prefect server on a Slurm login node, și setează adresa serverului tău în locul lui <server-host>:

# Optional: only for your own Prefect server
prefect config set PREFECT_API_URL=http://<server-host>:4200/api

Pasul 7: Stochează credențialele IBM Quantum​

Rulează qcsc-qrmi login după autentificarea în Prefect, deoarece salvează blocul qrmi-runtime:

qcsc-qrmi login

Răspunde la solicitări:

  1. Lipește cheia ta API IBM Cloud. Cheia nu este afișată.

  2. Apasă Enter pentru a folosi toate instanțele.

  3. Introdu numărul instanței implicite, 1 în exemplul următor.

  4. Introdu numărul sau numele backendului implicit, 4 (ibm_kingston) în exemplul următor.

# Output, with your answers after the prompts

Comanda afișează și o notă despre nodurile de calcul și linii [qrmi] pentru sqd_blocks.toml, pe care exemplul le omite (...). Nu ai nevoie de liniile [qrmi], deoarece fluxul de lucru citește instanța și backendul din blocul qrmi-runtime.

Comanda qcsc-qrmi are următoarele subcomenzi:

ComandăScop
qcsc-qrmi loginStochează cheia API, instanțele și backendurile și salvează blocul
qcsc-qrmi refreshGăsește din nou instanțele și backendurile cu cheia stocată
qcsc-qrmi listAfișează instanțele și backendurile, fără cheie
qcsc-qrmi checkVerifică dacă instanța blocului poate folosi backendul său

Instalează fișierul pe nodurile de calcul​

Pluginul SPANK citește qrmi_config.json pe fiecare nod de calcul, de la calea din plugstack.conf, adesea /etc/slurm/qrmi_config.json. Cere administratorului clusterului să instaleze ~/.qiskit/qrmi_config.json la acea cale. Instalează-l din nou după fiecare qcsc-qrmi login sau qcsc-qrmi refresh.

Păstrează Session Mode al blocului qrmi-runtime pe batch, deoarece pluginul SPANK obține QPU în batch mode.

Pasul 8: Creează mediul nodului de calcul​

Workerul QRMI rulează pe un nod de calcul, în propriul mediu. Creează-l din același checkout. Opțiunea --python păstrează ~/venv/qcsc-host activ:

cd "$QCSC_PREFECT"
uv venv ~/venv/qcsc-node -p 3.12
uv pip install --python ~/venv/qcsc-node/bin/python "qrmi[ibm]"
uv pip install --python ~/venv/qcsc-node/bin/python -e packages/qcsc-prefect-qiskit

Pachetul qrmi[ibm] oferă comanda task_runner. Tutorialul adaugă hook-ul de compilare SQD în acest mediu și folosește ~/venv/qcsc-node/bin/python ca python_executable din sqd_blocks.toml.

Verifică instanțele și backendurile stocate. Comanda nu afișează niciodată cheia:

qcsc-qrmi list
# Output
API key: set
premium-instance (premium, us-east) (default): ibm_boston, ibm_chicago, ibm_fez, ibm_kingston, ibm_marrakesh, ibm_phoenix, ibm_pittsburgh
open-instance (open, us-east): ibm_fez, ibm_kingston, ibm_marrakesh

Verifică dacă instanța implicită poate folosi backendul implicit:

qcsc-qrmi check
# Output
premium-instance (premium, us-east) can use ibm_kingston.

Verifică dacă Slurm rulează un job pe ambele noduri de calcul, inclusiv cu PMIx:

srun -N2 hostname
srun -N2 --mpi=pmix hostname
# Output of each command
c1
c2

Verifică mediul nodului de calcul și directorul de lucru pe un nod de calcul. Prima comandă nu afișează nimic atunci când importurile reușesc:

srun -N1 ~/venv/qcsc-node/bin/python -c "import qrmi, qcsc_prefect.integrations.qiskit.qrmi.worker"
srun -N1 ls ~/venv/qcsc-node/bin/task_runner
srun -N1 ls -ld "$QCSC_WORK_DIR"
